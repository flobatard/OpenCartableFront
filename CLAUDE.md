# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Projet

Front Angular 22 d'**OpenCartable**, plateforme pédagogique auto-hébergée (AGPLv3) : un prof authentifié (OIDC/Zitadel) compose des cours, les élèves les consultent via liens publics sans compte. Cadrage produit : `Descriptions.md`. Design system (source de vérité UI) : `DESIGN_SYSTEM.md`.

## Commandes

Node est géré par nvm ; dans un shell non-interactif, npm n'est pas sur le PATH :

```bash
export PATH="$HOME/.nvm/versions/node/v26.3.0/bin:$PATH"
```

```bash
npm start                              # dev server (4200)
npm run build                          # build prod + prerender de la home
npm test                               # vitest (jsdom)
npm test -- --include src/app/core/theme/theme.service.spec.ts   # un seul fichier
npm test -- --filter "ThemeService"    # par nom de suite/test
npm run serve:ssr:OpenCartableFront    # sert dist/ via Express (4000)
docker compose up --build              # conteneur SSR (4000)
```

Après tout changement touchant SSR/i18n/prerender, vérifier que `dist/OpenCartableFront/browser/index.html` contient bien le texte français rendu (pas de chaînes vides) : c'est le symptôme d'une régression du préchargement Transloco.

## Architecture et invariants

**Zoneless** (pas de zone.js — défaut Angular v22) : tout état partagé est exposé en **signaux** ; les souscriptions rxjs écrivent dans des signaux. Ne jamais ajouter `provideZoneChangeDetection`.

**Trois modes de rendu** (`src/app/app.routes.server.ts`) : `/` prerendered au build, `/auth/callback` client-only (il manipule URL et storage), `**` SSR. Toute nouvelle route doit choisir son mode ; une route qui touche `window`/`localStorage` sans garde ne peut pas être SSR/prerender. Une route protégée par `authGuard` doit être en `RenderMode.Client` (le guard renvoie `false` au serveur — jamais authentifiée au SSR, donc jamais prerendable) : cf. `:lang/subjects`.

**Couche données HTTP** : `SubjectService` (`src/app/core/subjects/`) est le patron des accès API. Un seul `HttpClient.get` par ressource, mis en cache via `shareReplay({ bufferSize: 1, refCount: false })`, état exposé en signaux (`tree`/`loading`/`error`) alimentés par la souscription rxjs. Le Bearer Zitadel est attaché **automatiquement** par l'intercepteur d'`angular-oauth2-oidc` à toute requête sous `environment.apiUrl` (`resourceServer.allowedUrls` dans `app.config.ts`) — ne pas ajouter de header manuel ; `apiUrl` inclut déjà `/api`. Fetch déclenché côté navigateur uniquement (guard `isPlatformBrowser`). Les helpers purs de l'arbre (recherche, chemin d'ancêtres, aplatissement, lignes de treeview) vivent dans `subject.utils.ts`, testés isolément. `EducationLevelService` (`src/app/core/education-levels/`) est le second exemplaire du patron (mêmes signaux + cache) ; ses helpers minimaux vivent dans `education-level.utils.ts` — on ne généralise **pas** `subject.utils.ts` pour ne pas coupler les deux pickers. Les libellés métier (`nom` des matières et des niveaux d'étude) viennent de l'API et **ne passent pas** par l'i18n.

`UserProfileService` (`src/app/core/users/`) est la variante **mutable** du patron : pas de `shareReplay` figé mais un signal `profile` source de vérité, une **promesse en vol partagée** (`ensureLoaded()` — callback et guard n'émettent qu'un GET, invalidée sur erreur pour permettre le retry), les mutations remplacent le signal (`saveProfile()` : le `PUT /users/me/profile` sert d'onboarding initial **et** d'édition de profil, sémantique remplacement, pas de refetch) et un `effect` purge le profil quand `AuthService.isAuthenticated()` retombe. La logique du formulaire de profil (forme du FormGroup typé, règles de cohérence, mapping payload, complétude) est **factorisée en helpers purs** dans `core/users/profile-form.ts`, partagés par l'onboarding et la page profil — les templates, eux, restent distincts (stepper vs page à plat). Piège d'ordre : `patchFormFromProfile` pose `systeme` avant les blocs, sinon la cohérence câblée viderait les niveaux patchés.

**Espace cours** (`core/courses/` + `features/courses/`) : `CourseService` est la variante mutable **multi-ressources** du patron — signaux `list`/`detail` sources de vérité **refetchés à chaque entrée de page** (pas de `shareReplay` : données mutables), mutations async (`createCourse`, `addBlock` — qui porte un méta titre/description optionnel —, `deleteBlock`, `reorderBlocks`, `updateBlockContent`, `updateBlockMeta`, `updateBlockResource` — PATCH dédié `{resource_id}` des blocs `document`, jamais mêlé au content ni au méta — et son miroir `updateBlockModule`, PATCH dédié `{module_id}` des blocs `module`) qui patchent localement le signal `detail` (depuis la réponse du back, **sauf `reorderBlocks` qui est optimiste** : il réordonne le signal **avant** le PUT et laisse l'appelant recharger sur erreur ; `#patchDetail` ne s'applique que si le détail affiché est le cours muté), purge à la déconnexion. **Quatre types de blocs, tous créables** : `texte`, `exercice`, `document` (pont nullable vers une ressource de la bibliothèque — `resource_id` en colonne ; supprimer la ressource supprime le bloc, FK CASCADE côté back) et `module` (pont nullable vers un module interactif de la bibliothèque de modules — `module_id` en colonne ; supprimer le module supprime le bloc, FK CASCADE côté back). Les blocs portent `titre`/`description` facultatifs (tous types, distincts du `content`). Helpers purs du formulaire de création dans `core/courses/course-form.ts` (motif `profile-form.ts`) ; ceux du méta titre/description d'un bloc dans `core/courses/block-meta-form.ts`, **partagés par la modale de création et l'éditeur** ; ceux du contenu document (`buildDocumentForm`, `payloadFromDocumentContent` — normalisation avec replis —, `payloadFromDocumentForm`) dans `core/courses/document-form.ts`. Pages : liste `courses` (cartes, badges matières/niveaux résolus dans les arbres — id inconnu = pas de chip), création `courses/new` (**déclarée avant** `courses/:id`, matching en ordre ; picker de niveaux filtré par le `systeme_scolaire` du profil), page cours `courses/:id` à **quatre onglets Blocs | Ressources | Modules | Aperçu** (tablist APG au motif `markdown-field`, ids ARIA par compteur de module ; panneaux en `@if` — pas de Monaco ici, rien à préserver ; **cyclage clavier ←/→ par index via `TAB_ORDER`** ; onglet actif reflété dans `?tab=` — Blocs = défaut donc param retiré, `resources`/`modules`/`preview` sérialisés — via `router.navigate([], {replaceUrl: true})`, deep-linkable ; le retour d'éditeur retombe sur Blocs) — onglet Blocs : liste = titre en gras + description ; **création via une modale** `block-create-dialog` saisissant titre/description, puis **redirection** vers l'éditeur du bloc créé ; « Modifier » sur **tous** les types ; **réordonnancement par glisser-déposer (poignée `grip-vertical` + `cdkDragHandle`, `@angular/cdk/drag-drop`) ou flèches ↑/↓ discrètes — poignée aussi opérable au clavier (↑/↓/Début/Fin), via helper pur `moveIdTo` ; le câblage DnD ne binde pas `cdkDropListData` ni n'appelle `moveItemInArray` (le signal `detail` reste seule source de vérité)** ; suppression en deux temps sans modale, désarmée au blur — onglet Ressources : composant `CourseResources` (voir ci-dessous) dont l'output `(deleted)` fait recharger le détail du cours par la page (les blocs document pointeurs ont été supprimés en cascade par le serveur) — onglet Modules : composant `CourseModules` (voir **Bibliothèque de modules interactifs**), même contrat `(deleted)` — onglet Aperçu : composant `CoursePreview` (voir ci-dessous), **vue élève** du cours entier —, éditeur de bloc `courses/:id/blocks/:blockId`, éditeur de module `courses/:id/modules/:moduleId`. Toutes protégées `[authGuard, onboardingGuard]` + `RenderMode.Client`, params lus en snapshot (pas de `withComponentInputBinding` dans ce projet). Le header porte le lien « Mes cours » quand la session est ouverte.

**Export/import de cours** (`core/courses/course-transfer.utils.ts` + `features/courses/course-import-dialog/`) : l'**export** (bouton « Exporter » de l'en-tête de la page cours, poussé à droite par `margin-left: auto`) télécharge l'archive `.zip` du back via `CourseService.exportCourse` — **premier `responseType: 'blob'` du projet** : l'endpoint exige le Bearer (URL sous `apiUrl`), donc pas de `window.open` comme pour les URL S3 présignées — puis `downloadBlob` (`URL.createObjectURL` + `<a download>` éphémère, browser-only, stubs dans les specs : jsdom n'implémente pas `createObjectURL`) sous un nom calculé **côté front** par `courseExportFilename` (le `Content-Disposition` du back n'est pas lisible sans `expose_headers` CORS — assumé) ; échec → toast (message traduit par l'appelant, motif `CourseShare.copy()`). L'**import** (bouton « Importer » du header de « Mes cours », groupé avec le CTA dans `.course-list__actions`) ouvre `CourseImportDialog` — `<dialog>` natif au motif `block-create-dialog`, mais qui appelle le service **elle-même** (motif `CourseResources`) : pré-contrôle 500 Mo (`MAX_IMPORT_BYTES`, miroir de `TRANSFER_MAX_ZIP_BYTES` back), puis `CourseService.importCourse` — **premier POST `FormData` multipart du projet** : ne JAMAIS poser de `Content-Type` manuel, le navigateur écrit le boundary — dont la progression alimente le signal **`importState`** (`idle|uploading|processing|error` + `progress`, purgé à la déconnexion ; `processing` = corps envoyé, le back parse et pousse vers S3) ; erreurs par statut (413/422/503 → clés dédiées, sinon générique), fermeture bloquée pendant l'envoi, puis toast succès, insertion du cours en tête de `list` et **navigation vers le cours recréé** (nouveaux ids — le back remappe aussi les références `oc-resource:`/`oc-module:` du markdown). Tout spec montant une page qui embarque la modale doit fournir `importState`/`importCourse` dans son mock de `CourseService`. Clés i18n `courses.import.*`, `courses.list.import`, `courses.blocks.export`/`exporting`/`exportError`.

**Bibliothèque de ressources** (`core/resources/` + `features/courses/course-resources/`) : `ResourceService` est un exemplaire de plus du patron mutable (signaux `list`/`listLoading`/`listError` refetchés à chaque entrée d'onglet, garde `#courseId` sur les patchs locaux, purge à la déconnexion) plus un signal `uploadState` (`idle|presigning|uploading|confirming|error` + `progress`, un upload à la fois). **Upload en trois temps** : POST presign (type dérivé du MIME par `resourceTypeFromMime`, repli `application/octet-stream`) → **PUT direct navigateur→S3 via `HttpClient`** — hors `environment.apiUrl`, donc l'intercepteur OIDC n'attache **pas** de Bearer (`allowedUrls`), c'est voulu ; ⚠ le header `Content-Type` doit être **strictement** le mime déclaré au presign (figé dans la signature S3) ; `reportProgress` alimente la progression — → POST confirm **sans body** (la ressource devient `disponible`, aucun bloc créé). Helpers purs dans `core/resources/resource.utils.ts` (`resourceTypeFromMime`, `isPdfResource` — PDF détecté par le mime `application/pdf`, **jamais un nouveau `ResourceType`** —, `resourceTypeLabelKey` — clé du badge « PDF » dédié parmi les `document`, choisie par code —, `formatBytes` — formatage maison déterministe, pas d'`Intl` — et `resourceContentUrl`, cf. Export PDF). `getDownloadUrl(courseId, resourceId, disposition = 'attachment')` : la variante `'inline'` ajoute `?disposition=inline` (affichage navigateur, consommée par `resource-view`) ; sans argument, aucun query param — la requête historique des autres consommateurs est inchangée. `CourseResources` (présentationnel + service) : liste (nom, badge type, taille, date, `en_attente` atténuée — bordure dashed, texte `--text-secondary`, téléchargement désactivé), upload par `<input type="file" hidden>` (input vidé après choix pour permettre le retry), **renommage inline** (FormControl public `renameControl`, Échap annule ; seul le nom affiché change, la clé S3 reste figée), **aperçu en modale** (bouton « Voir » sur les images et PDF `disponible` — `ResourcePreviewDialog`, `shared/resource-preview-dialog/`, `<dialog>` natif au moule resource-picker élargi à 960px, qui **embarque `CoursePreviewDocument`** plutôt que de dupliquer présignature et bypass ; son `(close)` natif remet la ressource à `null` pour **démonter l'embed** — l'effect de l'embed ne re-présigne que si la ressource change, une réouverture après expiration du TTL afficherait sinon une URL morte), téléchargement (`getDownloadUrl` puis `window.open(url, '_blank', 'noopener')` dans le composant), suppression en deux temps désarmée au blur. Le badge de type passe par `resourceTypeLabelKey` (badge « PDF » — idem dans le picker d'insertion `resource-picker-dialog`). Clés i18n sous `courses.resources.*` (dont `types.pdf`, `view`), `resourcePreview.*` et `courses.tabs.*`.

**Bibliothèque de modules interactifs** (`core/modules/` + `features/courses/course-modules/` + `shared/module-runner/` — J4, anticipé) : un module = **code HTML/CSS/JS écrit par le prof, stocké en base** (pas de S3 — décision actée, cf. Descriptions.md §5.5), exécuté dans une **iframe sandbox à origine opaque**. `ModuleService` (`core/modules/module.service.ts`) est un exemplaire du patron mutable (signaux `list`/`listLoading`/`listError` refetchés à chaque entrée d'onglet, garde `#courseId`, purge à la déconnexion) **sans upload** ; la liste est légère (`ModuleSummary`, jamais le code), le détail passe par **`getModule(courseId, id)`** — promesses partagées dans un petit cache par id, invalidé par `updateModule`/`deleteModule`/`loadList`, entrée en échec retirée (retry possible) — consommé par chaque embed affiché (un GET par module, pas par re-rendu) ; `updateModule` = PATCH partiel (renommage et/ou autosave du code par le même endpoint). `CourseModules` (onglet Modules, motif `CourseResources`) : création inline (titre → `createModule` → **redirection vers l'éditeur du module créé**), renommage inline (Échap annule), lien « Modifier », suppression en deux temps ; `(deleted)` → la page recharge le détail (blocs `module` pointeurs supprimés en cascade).

**Exécution sandbox** (`shared/module-runner/` — invariants de sécurité, ne pas « simplifier ») : `ModuleRunner` (`app-module-runner`, inputs `html`/`css`/`js`/`title`, output `moduleEvent`) compose le document via le helper pur **`composeModuleDocument`** (`module-document.ts` : **CSP `MODULE_CSP` en tête du head**, puis CSS, HTML, **bridge** injecté AVANT le JS du prof — `</script`/`</style` neutralisés en `<\/…`) et le pose **impérativement** (`iframe.srcdoc = doc` dans un effect — **jamais `[srcdoc]`** : le sanitizer Angular striperait les scripts, et on n'ajoute aucun `bypassSecurityTrustHtml` hors markdown-view). L'attribut **`sandbox="allow-scripts allow-forms allow-modals"` est statique dans le template et ne contient JAMAIS `allow-same-origin`** → origine opaque (`'null'`) : ni cookies, ni storage, ni tokens, ni DOM parent ; le **réseau sortant est BLOQUÉ par la CSP du srcdoc** (`default-src 'none'` ; autorisés : inline, **`'unsafe-eval'`** — expressions saisies évaluées type grapheur, aucune capacité nouvelle dans une iframe opaque sans réseau, résidu = self-XSS élève confiné — et assets `data:`/`blob:` ; `form-action 'none'` — décision actée, révise le « CDN autorisés » initial ; résidus assumés : la navigation par clic de lien, visible et confinée par le sandbox, et l'héritage de la CSP de la page hôte par le srcdoc — une future CSP d'en-tête posée par l'infra devra tolérer `'unsafe-eval'`). Le bridge (`oc-module:*`) fait l'**auto-resize** (ResizeObserver → `postMessage` avec `targetOrigin '*'`, obligatoire depuis une origine opaque et sans secret dans le payload) et expose **`window.ocModule.emit(name, data)`** (événements applicatifs, ex. futur score). Côté parent : listener `message` retiré au destroy, validation par **provenance** (`event.source === iframe.contentWindow` + `event.origin === 'null'`) puis par **forme** (`parseModuleMessage`, pur), hauteur clampée (`clampFrameHeight`, [80, 4000] px) bindée `[style.height.px]`. `ModuleEmbed` (`app-module-embed`, inputs `courseId`/`moduleId`) résout l'id via `getModule` (effect stale-guardé) et délègue à `ModuleRunner` — états « aucun module » / « module manquant » (motif `.course-resource--missing`) ; son hôte porte **`data-oc-module-id`** (clé de la note d'impression). Cadre DS : dashed + badge « interactif ».

**Éditeur de module** (`features/courses/module-editor/`, route `courses/:id/modules/:moduleId`, RenderMode.Client, params en snapshot) : coquille au motif block-editor — **trois Monaco HTML | CSS | JS** commutés par tabs (tablist APG, ids par compteur de module, panneaux masqués par **`[hidden]` jamais `@if`** — Monaco vit dans les trois) via l'input `language` du markdown-editor, **preview live** `app-module-runner` en grid 50/50 (motif markdown-playground, empilé <900px), le tout composé avec le **panneau assistant** (`app-course-chat`, monté avec `courseId`/`moduleId`) dans un **espace de travail redimensionnable au motif block-editor** — grille des panes en `.module-editor__panes` (flex-basis `--editor-basis`, défaut 68 % : la colonne porte deux panes), poignée `separator` (drag + clavier, mêmes bornes 15–85), repli par `[hidden]` (bascule « Assistant » de l'en-tête, clés `courses.editor.*` réutilisées), bouton de réouverture <900px ; **hauteurs** : le pane éditeur remplit la hauteur de l'espace de travail (ligne de grille **explicite `minmax(0,1fr)`** — une ligne implicite `auto` se calerait sur le contenu et écraserait Monaco —, panneau actif `flex:1`, jamais défilé — pas de sticky : c'est le pane **aperçu qui défile dans sa propre colonne** quand le module est long) ; **deux seuils distincts** : <900px seul le chat passe dessous (min-height 260px, les panes cèdent par `flex-shrink`) — éditeur | aperçu restent côte à côte sur toute la largeur — et <640px les panes s'empilent (éditeur 420px fixes, défilement commun) — **preview seedée depuis le module chargé** (les `setValue` d'init n'émettent pas — signaux posés directement, sinon preview vide à l'ouverture) puis alimentée par les trois `valueChanges` **débouncés 500 ms** (chaque recomposition recharge l'iframe) ; **autosave** `merge(html,css,js) → debounceTime(1500) → concatMap` (jamais switchMap), payload relu à l'envoi, `#lastSaved` JSON, flush au destroy **enchaîné derrière le PATCH en vol** (`#inFlightSave` — takeUntilDestroyed annule la file, pas la requête partie : sans ce chaînage l'ancien code pourrait écraser le nouveau) — pipeline au motif block-editor. Les trois `FormControl` sont **publics** (jsdom les pilote, jamais Monaco) ; init unique depuis `getModule`, jamais réécrits. Le renommage vit dans l'onglet Modules, pas ici. Clés i18n `courses.modules.*`, `courses.moduleEditor.*`, `courses.editor.module.*`, `moduleEmbed.*`, `modulePicker.*`.

**Modules intégrés au markdown** (`core/markdown/course-module-ref.ts`, miroir de `course-resource-ref.ts`) : référence stable **`oc-module:<id>`**, id **validé en forme UUID** (`isModuleId`, garde de sécurité : l'id finit interpolé dans l'URL du `GET /modules/{id}` — un id forgé, path traversal compris, n'atteint jamais l'API) ; l'override des renderers `link` **et `image`** de `courseMarked` (testés AVANT `parseResourceRef` ; la syntaxe `![…]` rend le même placeholder — sans ça l'`<img src="oc-module:…">` serait vidé par DOMPurify, perte silencieuse) émet un `<span class="course-module-embed" data-oc-module-id>` inerte portant le texte du lien en repli (les `data-*` survivent à DOMPurify) ; **pas de passe async** — `markdown-view` monte un **`ModuleEmbed` par placeholder** dans le même `afterRenderEffect` que les extensions (`#mountModuleEmbeds` : `createComponent({hostElement})` + `setInput`, import dynamique **mémoïsé** de ModuleEmbed — l'iframe reste hors des chunks sans module —, garde `courseId` non nul : hors contexte cours le span reste une note inerte, **re-garde `isModuleId` sur l'attribut** — un `data-oc-module-id` peut aussi arriver par du HTML brut sans passer par `parseModuleRef` —, même stale-guard/onCleanup destructeur de refs). Insertion : `buildModuleMarkdown` → `[titre](oc-module:<id>)`.

**Aperçu global du cours** (`features/courses/course-preview/`) : `CoursePreview` (`app-course-preview`, onglet Aperçu) rend **tous les blocs prévisualisables les uns à la suite des autres, dans l'ordre du back** — le cours tel que le verra l'élève. **Vue élève** : réponses attendues des exercices **masquées** (via `exerciseMarkdownFromContent`, cf. `exercise-form.ts`). Rendu **par bloc** (pas de markdown concaténé : les documents s'intercalent et ne sont pas du markdown) : `texte` (`content.markdown`) et `exercice` (sujet + énoncés) passent par `app-markdown-view` ; `module` par `app-module-embed` (iframe sandbox résolue par `block.module_id` — module supprimé → notice ; un bloc **encore vide est masqué en entier**, vue élève : sa notice « Aucun module choisi » est un message d'autorat qui partirait sinon dans l'aperçu et le PDF) ; `document` par `CoursePreviewDocument` (`app-course-preview-document`, **dans `shared/course-blocks-view/`**, partagé avec les vues élèves) — **média intégré** (image/audio/vidéo affichés en ligne via l'URL présignée `getDownloadUrl`, résolue au montage dans un `effect` stale-guardé), **PDF embarqué en iframe** (viewer natif du navigateur : `isPdfResource` ⇒ presign `'inline'`, `[src]` posé via `bypassSecurityTrustResourceUrl` — URL issue **exclusivement** du résolveur, second et dernier bypass resource-URL du repo après geogebra-view — **sans `sandbox`** : le viewer PDF de Chrome ne se charge pas dans une iframe sandboxée, l'isolation vient de l'origine S3 cross-origin et du Content-Type signé au PUT ; le champ éditorial `affichage` du bloc est désormais **lu** : `telechargement` force la carte ; rangée « Ouvrir dans un onglet » — presign **frais**, jamais l'URL de l'iframe — / « Télécharger » sous l'embed, chemin nominal iOS Safari qui ne rend que la 1re page) avec **repli carte téléchargeable** pour les autres `document` et sur échec de présignature ; ressource supprimée/inconnue → notice `documentMissing`. Présentational + services (`CourseService.detail` déjà chargé par la page hôte, `ResourceService.loadList` déclenché au montage — couvre le deep-link `?tab=preview` à froid). Les deux `app-markdown-view` (texte/exercice) reçoivent `[courseId]` pour résoudre les ressources `oc-resource:` intégrées au markdown (cf. **Rendu markdown de cours**) — indépendant du bloc `document`, résolu par `CoursePreviewDocument`. La barre d'actions porte aussi le bouton **« Style de lecture »**, `#previewContent` reçoit `[style]` des réglages du cours et les markdown-view internes passent `[showSettings]="false"` (cf. **Style de lecture du rendu**). Client-only (`markdown-view` et présignature touchent `window`). Clés i18n sous `courses.preview.*` et `courses.tabs.preview`.

**Éditeur Monaco** (`shared/markdown-editor/`, CVA `string` enrobant `ngx-monaco-editor-v2`) — pièges vérifiés dans le source du wrapper, ne pas « simplifier » :
- Monaco est **servi en AMD depuis les assets** (`angular.json` copie `node_modules/monaco-editor/min/vs` → `/monaco/vs`, ~16 Mo), jamais bundlé ; `NGX_MONACO_EDITOR_CONFIG` est fourni par le composant avec un **baseUrl absolu `/monaco/vs`** (le défaut du wrapper est relatif à la page → cassé sur les routes profondes). Workers et CSS monaco s'auto-configurent depuis ce chemin.
- Le wrapper **dispose et recrée l'éditeur à chaque changement de référence de `[options]`** → options à référence stable : constante module enrichie par un `computed` sur l'input **`language`** (défaut `'oc-markdown'` ; `html`/`css`/`javascript` built-in pour l'éditeur de module — **statique par instance**, ne jamais binder un langage variable) ; le thème passe par `monaco.editor.setTheme` global (effect sur `ThemeService.theme()`, snapshot initial hors du computed), **jamais** par les options.
- Le wrapper **n'est pas SSR-safe** (touche `window`/`document` sans guard) → toute page hôte en `RenderMode.Client` + `@if (isBrowser)` dans le composant.
- Relais CVA avec **guard anti-écho** (le wrapper ré-émet la même valeur après un `writeValue`) ; `remeasureFonts()` quand JetBrains Mono finit de charger (sinon curseur décalé).
- En jsdom (specs), le loader AMD ne se charge jamais → le wrapper est **inerte par construction** : les specs pilotent les `FormControl`, jamais monaco.
- Méthode publique **`insertAtCursor(text)`** (pour l'insertion de ressource, cf. `markdown-field`) : capte l'instance `IStandaloneCodeEditor` émise par `(onInit)` (auparavant jetée), `executeEdits` + `focus`. La mutation du modèle **passe la garde anti-écho et se propage seule** au contrôle hôte — pas de `#onChange` manuel ; **no-op** tant que monaco n'est pas initialisé (SSR/jsdom).

**Ressources de la bibliothèque intégrées au markdown** (`core/markdown/course-resource-ref.ts` — schéma **partagé par le rendu ET l'insertion**) : le markdown stocke une **référence stable** `oc-resource:<id>` (l'`id` de `CourseResource`, **jamais** l'URL présignée — TTL court, elle expirerait). méthode publique `print()`) et `course-preview` (bouton « Télécharger en PDF », **cours entier**, `viewChild` `previewContent`). **`transformForPrint`** (pure, testée jsdom) transforme le clone en place : les extensions markdown **non imprimables** (`data-oc-printable ≠ "true"`, ex. iframe GeoGebra) → note « contenu interactif » (les imprimables, SVG JSXGraph, sont clonées telles quelles) ; les **modules interactifs** (tout `[data-oc-module-id]` — embeds `oc-module:` du markdown ET hôtes `ModuleEmbed` des blocs module de l'aperçu) → note dédiée `moduleEmbed.printFallback` **+ lien vers la page du cours** (`courseContentUrl(lang, courseId)`, même classe `.oc-print__extension-note`), jamais imprimables ; puis, keyé par `data-oc-resource-id`, les **images restent** (l'URL présignée est encore valide à l'instant de l'impression), l'audio/vidéo **et l'iframe d'un PDF embarqué** (libellé = son `title` ; sans cette branche l'iframe traverserait le dispatch par tag et sortirait en cadre vide) → note renvoyant vers l'URL stable, les liens de ressource → `href` réécrit vers l'URL stable, la carte d'un bloc document → nom cliquable + URL en clair copiable. **URL stable** : `resourceContentUrl(lang, courseId, resourceId)` (`resource.utils.ts`) pointe la **route front de redirection** `/:lang/courses/:id/resources/:resourceId` (`features/courses/resource-view/`, protégée `[authGuard, onboardingGuard]` + `RenderMode.Client`, motif `AuthCallback`) : elle présigne de manière authentifiée via `getDownloadUrl(..., 'inline')` puis `redirectTo(url)` (`location.replace` — indirection publique car non espionnable en jsdom) redirige le navigateur vers S3 ; 404/409 → message i18n `courses.resourceView.*` + lien retour au cours. **Pérenne**, contrairement à l'URL présignée à TTL court, donc utilisable dans un PDF persistant — mais **réservée au prof propriétaire du cours** tant que le régime élève J2 (token de partage) n'existe pas (les gateways back `/content`/`/public` ont été supprimées). Toujours **absolue** via `environment.siteUrl` (champ d'environnement jamais remplacé par `/api`) ; la langue est fournie par `LanguageService.lang()` injecté dans `PrintService` (`transformForPrint` prend `lang` en paramètre). Pour que l'export retrouve les ressources, `buildResourceElement` (`course-markdown.ts`) **repose `data-oc-resource-id`** (`RESOURCE_REF_ATTR`) sur chaque élément résolu (inerte à l'écran, survit à DOMPurify via `data-*`). **`keepHeadingsWithContent`** (pure, testée) enveloppe chaque titre du contenu avec les quelques blocs qui le suivent (borné `HEADING_KEEP_FOLLOWING`) dans un `.oc-print__keep` `break-inside: avoid` → pas de titre orphelin en bas de page. Invariants de `_print.scss` : `#oc-print-root` est rendu **hors-écran** (`left:-100vw`) hors impression, **jamais `display:none`** (ses images ne se chargeraient pas avant `print()`) ; en `@media print`, `body > *:not(#oc-print-root)` est masqué, le conteneur **force les tokens de lecture clairs** (texte foncé sur blanc même en thème sombre), `@page { margin: 0 }` supprime les en-têtes/pieds ajoutés par le navigateur (les marges de lecture reviennent par le padding), **un bloc de cours par page** (`break-before: page` sur `.course-preview__block + .course-preview__block`), typographie d'impression en unités **pt** mais **multipliée par les facteurs de style du cours** (`--course-font-scale`/`--course-line-scale`/`--course-heading-scale`/`--course-para-scale`, cf. **Style de lecture du rendu**) → les réglages d'écran se reflètent au PDF, la largeur de lecture étant neutralisée (`max-width:none`). Le conteneur d'actions flottantes `.markdown-view__actions` et la rangée `.course-preview-document__actions` (sous un PDF embarqué) sont masqués à l'impression. Clés i18n : `markdownView.print`, `courses.preview.downloadPdf`/`pdfMediaNote`, `markdownExtensions.printFallback` (+ sections `print` des pages de doc).

**Composants partagés** (`src/app/shared/`) : composants réutilisables transverses. `SubjectPicker` y est le premier `ControlValueAccessor` (valeur = `id` du nœud, utilisable en Reactive Forms) ; tout nouveau form control suit ce modèle (provider `NG_VALUE_ACCESSOR` + `forwardRef`, `writeValue`/`registerOnChange`/`setDisabledState`, navigation clavier + ARIA treeview). `EducationLevelPicker` est le premier CVA **multi**-sélection : valeur = `string[]` d'ids toujours émise en ordre d'arbre (jamais `null`, ids inconnus préservés) ; pattern volontairement plus simple — disclosure + cases à cocher natives (pas de treeview ARIA ni de recherche, arbre ~22 nœuds toujours déplié), chips « badge niveau » (slate) sous le champ. `EducationLevelPicker` accepte un input `systeme` (filtre les **racines** de l'arbre au système scolaire donné ; `null` = tous) — le contrat « ids inconnus préservés » demeure : c'est au parent de vider la valeur quand le système change. `SubjectMultiPicker` (`shared/subject-multi-picker/`) est le CVA multi-matières **par composition** : il embarque le `SubjectPicker` mono (non modifié) comme champ d'ajout via un `FormControl` interne réinitialisé à chaque sélection, valeur = `string[]` en ordre d'ajout dédoublonné, chips « badge matière » (indigo). **Piège de nommage** : `SubjectLevel` et les clés `subjects.level.*` désignent la *profondeur* de l'arbre des matières ; tout ce qui touche aux niveaux d'étude vit sous `EducationLevel*` / `educationLevels.*`. Pièges : un `viewChild()` ne peut pas être posé sur un champ privé ES (`#`) — le marquer `protected` ; et ne pas nommer une variable de template (`#foo`) comme un signal du composant (le template résout la ref avant le signal).

**Notifications globales & spinner** (`core/notifications/` + `shared/snackbar/` + `shared/spinner/`) : `NotificationService` est la variante **in-memory** du patron à signaux (pas de HTTP) — file `toasts` source de vérité, API `error/warning/info/success/dismiss`, ids par compteur incrémental (**jamais** `Date.now()`/`Math.random()`), auto-fermeture par `setTimeout` gardée `isPlatformBrowser` (aucun timer au SSR), dédoublonnage des messages identiques déjà visibles ; les émetteurs poussent un `message` **déjà traduit** (le service et le composant ignorent l'i18n, comme les libellés métier). `Snackbar` (monté **une seule fois** dans `app.html`, ancré bas-gauche, `z-index` élevé, `pointer-events: none` sur le conteneur / `auto` sur les toasts) rend la file : `role="alert"` pour une erreur / `role="status"` sinon, liseré gauche de la teinte **500** sémantique + glyphe distinctif (l'info n'est **jamais** encodée par la seule couleur, et 500 reste un aplat, jamais du texte). Câblage actuel : **seul `AuthService`** l'alimente (toast `loginError` quand la discovery échoue au login, `connectionError` quand le refresh silencieux échoue au bootstrap) — `AuthService` reste seul importeur d'`angular-oauth2-oidc`, il ne fait qu'appeler ce service applicatif ; brancher les autres sources (HTTP, données) plus tard sans refonte. `Spinner` (design system, `role="status"` + label `.sr-only` « Chargement… » par défaut, tailles `sm/md/lg`, anneau CSS coloré par `--color-primary`, rotation figée en `prefers-reduced-motion` → repli statique) recouvre l'éditeur Monaco tant que `ready()` (ex-`#ready`, exposé en lecture) est faux dans le markdown-editor. Les clés vivent sous `notifications.*` et `common.loading` (fr/en symétriques) ; l'utilitaire `.sr-only` est global (`_base.scss`). Doc UI : §8 de `DESIGN_SYSTEM.md`.

**Chaîne i18n (fragile, ne pas "simplifier")** — Transloco fr/en :
- Le loader (`src/app/core/i18n/transloco-loader.ts`) passe par des `import()` dynamiques de JSON, **pas** par HTTP : au prerender il n'y a aucun serveur pour répondre à une URL relative.
- Un `provideAppInitializer` dans `app.config.ts` précharge la langue active avant le premier rendu — sans lui, le HTML prerendered sort avec des chaînes vides.
- La langue persistée de l'utilisateur est restaurée **après** l'hydratation (`afterNextRender` dans `App`) : la restaurer plus tôt fait diverger le premier rendu client du DOM serveur (erreur NG0500).
- Traductions dans `src/app/i18n/{fr,en}/` — un JSON par clé racine (`courses.json`, `docs.json`…) réassemblés en objet plat par le barrel `index.ts` de chaque langue (un seul `import()` du barrel = un seul chunk lazy par langue). Garder les deux arborescences symétriques — gardé par le spec `src/app/i18n/i18n-parity.spec.ts` ; ajouter un domaine = un fichier par langue + une ligne dans chaque barrel.
